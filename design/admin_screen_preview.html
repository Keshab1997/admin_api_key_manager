What changed, and why it is safe for the host app:
every colour is a ColorScheme role, so the screen follows whatever theme the app installs — a host seeded on brand blue gets brand blue.
The three state colours are a ThemeExtension (KeyAdminPalette): a host that already owns a palette registers its own, and a host that registers nothing gets the defaults above. State is always a label + colour, never colour alone.
Keys are masked, reveal is per-row and off by default, and the add-form input is obscured — the old screen showed the full secret in plain text in the list.
The Provider groups screen writes admin_key_groups, which until now only existed as data: enabling a provider, ranking it, or overriding a cooldown meant editing Firestore by hand. An empty cooldown field means “use the built-in default” — distinct from 0, which would retry a failing key immediately. Nothing is written until an admin changes something.
